# CPUの強さ調整メモ

CPUの強さを変えたときの記録です。各回の「変更前の設定」と「戻し方」を見れば、その前の強さに戻せます。

---

## 2026-11-21 Lv5・Lv6の弱体化（うっかりの導入）

### 何を変えたか

| 対象 | 変更内容 |
|---|---|
| うっかり（新しい仕組み） | 毎手、決まった確率で本来より浅く読んで指す。うっかりした手では詰み筋の探索もしない。自爆、王手の放置、1手詰めの見逃し、相手に1手詰めを与えることは、うっかりしても起きない |
| CPUが先手のときの別設定（新しい仕組み） | CPUが先手のときだけ、別のうっかり率を使う。CPUが先手かどうかは手数の偶奇で判定する |
| 詰み筋探索 | 「自分の詰みを探す（攻め）」と「相手の詰みを防ぐ（守り）」を別々に入り切りできるようにした |
| Lv5 | 毎手60%の確率で1手読みになる |
| Lv6 | うっかりを追加し、詰み筋探索は攻めだけにした |
| 説明文 | Lv5とLv6の説明文を変えた |
| Lv1〜4、ルール、持ち時間 | 変えていない |

変更したファイル：

- `src/core/ai.ts`
- `src/ui/cpuProfile.ts`
- `tests/ai.test.ts`

**変更の理由：** 最強のLv6が人間にはほぼ勝てない強さだったため。「勝てない相手を作るのは意味がない」という方針に合わせた。

1手あたりのミス率の目標は次のとおり。表記は「詰みを逃す 1手/3手/5手」・「相手に詰みを許す 1手/3手/5手」で、単位は%。

| レベル | 目標 |
|---|---|
| Lv4 | 0/55/65・0/10/15 |
| Lv5 | 0/30/50・0/5/10 |
| Lv6 | 0/10/30・0/2/5 |

### 変更後の設定（現在）

`src/core/ai.ts` の `LEVEL_PARAMS`：

```ts
  5: { depth: 2, timeMs: 2200, ...SURE, margin: 2, rootCap: 0, replyCap: 0, ...NO_THREAT, slip1: 0.6 },
  6: {
    depth: 3, timeMs: 6000, ...SURE, margin: 0, rootCap: 0, replyCap: 0, ...NO_THREAT,
    attack: 3, slip1: 0.15, slip2: 0.3, asFirst: { slip1: 0.25, slip2: 0.45 },
  },
```

| | 全力時の読み | うっかり | 詰み筋探索 | 考える時間の上限 |
|---|---|---|---|---|
| Lv5 | 2手 | 1手読み60% | なし | 2.2秒 |
| Lv6（CPUが先手） | 3手 | 1手読み25%、2手読み45% | 攻めのみ（自分の5手詰め） | 6秒 |
| Lv6（CPUが後手） | 3手 | 1手読み15%、2手読み30% | 攻めのみ | 6秒 |

項目の意味：

| 項目 | 意味 |
|---|---|
| `slip1` | 1手読み（Lv4相当）になる確率 |
| `slip2` | 2手読み（変更前のLv5相当）になる確率 |
| `asFirst` | CPUが先手のときに使う値 |
| `attack` | 自分の詰みを探す範囲（自分の手番数。3なら5手詰めまで） |
| `defence` | 相手の詰みを防ぐ範囲（同上。0で使わない） |

### 変更前の設定（戻すとき用）

`src/core/ai.ts` の `LEVEL_PARAMS`。今のコードの書き方に合わせてある：

```ts
  5: { depth: 2, timeMs: 2200, ...SURE, margin: 2, rootCap: 0, replyCap: 0, ...NO_THREAT },
  6: { depth: 3, timeMs: 6000, ...SURE, margin: 0, rootCap: 0, replyCap: 0, ...NO_THREAT, attack: 3, defence: 3 },
```

- Lv5：2手読み。うっかりなし。
- Lv6：3手読みに加え、詰み筋探索を攻め・守りとも3手番（5手詰め）まで行う。うっかりなし。

`src/ui/cpuProfile.ts` の説明文：

```ts
  5: { name: '上級者', desc: '2手先まで読み、王手で追い詰めてきます。' },
  6: { name: '最強', desc: 'さらに深く読み、相手の罠まで見抜く最高レベル。' },
```

### 戻し方

1. `src/core/ai.ts` の `LEVEL_PARAMS` の5と6を、上の「変更前」に置き換える。
   - うっかりの仕組みはコードに残るが、値が0なら変更前と同じ強さで指す。
   - 乱数の引き方が1回増えているため、同じシードでも手は変わりうる。強さの分布は同じ。
2. `src/ui/cpuProfile.ts` の説明文を、上の「変更前」に戻す。
3. `tests/ai.test.ts` のテスト「levels 5 and 6 sometimes read shallower (うっかり) …」を削除する。うっかりが0だと失敗するため。他のテストはそのまま通る。
4. `npm test` と `npm run build` で確認する。

一部だけ戻す・調整する場合：

- **Lv5のうっかり率だけ変える：** `slip1: 0.6` を書き換える。100〜150局での実測は次のとおり。

  | `slip1` | 3手詰めを見逃す率（目安） | 対Lv3 | 対Lv4 |
  |---|---|---|---|
  | 0.6（現在） | 約30% | 82% | 74% |
  | 0.4 | 約20% | 89% | 84% |
  | 0.2 | 約10% | 92% | 91% |
  | 0（変更前） | 0% | 98%（旧方式） | 88%（旧方式） |

- **Lv6を強く・弱くする：**
  - `slip1` と `slip2` を下げると強く、上げると弱くなる。
  - 先手時だけ変えるなら `asFirst` を書き換える。
  - 相手の5手詰めも防がせるなら `defence: 3` を足す（変更前と同じ）。

### 計測結果（比較用）

**1手あたりのミス率（%）**

実戦32局から取り出した340局面で計測した。王手・詰めろが続く手順を5手詰めまで全探索して判定している。

| | 変更前 | 変更後 |
|---|---|---|
| Lv4 | 0/51/60・0/9/8 | 同じ（変更なし） |
| Lv5 | 0/0/48・0/2/5 | 0/31/57・0/6/7 |
| Lv6 | 0/0/0・0/0/0 | 0/11/24・0/2/3 |

変更後のLv6は、CPUが先手のとき 0/19/35・0/3/2、後手のとき 0/3/7・0/1/5。

**勝率**

変更後の総当たり（各50戦、行のレベルの勝率）：

| | Lv1 | Lv2 | Lv3 | Lv4 | Lv5 |
|---|---|---|---|---|---|
| Lv2 | 88% | – | | | |
| Lv3 | 98% | 82% | – | | |
| Lv4 | 100% | 92% | 68% | – | |
| Lv5 | 98% | 96% | 86% | 70% | – |
| Lv6 | 100% | 100% | 94% | 92% | 84% |

変更後の主な比較：

| 対戦 | 結果 |
|---|---|
| 新Lv6 対 旧Lv5 | 83勝67敗（55%） |
| 新Lv6 対 旧Lv5（Lv6が先手） | 76% |
| 新Lv6 対 旧Lv5（Lv6が後手） | 35% |
| 新Lv5 対 Lv3（150局） | 82% |
| 新Lv5 対 Lv4（150局） | 74% |

変更前のLv6（各50戦）は、Lv1〜Lv5に対して 100% / 100% / 98% / 96% / 84%。CPUが先手のときは全勝だった。

**1手の計算時間**

| | 変更前 | 変更後 |
|---|---|---|
| Lv5 | 平均0.2秒 | 平均0.1秒 |
| Lv6 | 平均1.7秒 | 平均0.8秒（最大6秒） |

画面上は、どのレベルも最低0.8〜1.2秒「考える」演出が入る。

### 計測方法（ローカルのツール、Git管理外）

計測ツールは `.claude/bench/` にある。このフォルダはGitに入っていない。

| 用途 | ツール | 方法 |
|---|---|---|
| 勝率 | `ladder3.ts` | `RP=1` で、先手の1手目だけをランダムにする。1組50戦が基本。`OFF` を付けると別の初手で計測でき、`OVR` で一時的に設定を変えられる |
| ミス率 | `mpool.ts` | 実戦から局面を集める |
| ミス率 | `miss.ts` | 正解判定を行う |
| ミス率 | `modes.ts` | 設定を変えた場合のミス率を測る |
